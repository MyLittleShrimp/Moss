# 发布节奏与平衡建议（G10）

建议采用“分钟内有反馈、每天有收获、每周有惊喜”的分层节奏。不能简单把全游戏时间统一乘几十倍：最远旅行可以七到十天，但基础资源和近郊旅行仍要可接近。

这不是精确归期提示。游戏只告诉玩家大致时间级别，实际回程随机；雨天 / 绕路延长但不超过此路线最大时长，忘带东西可能提前折返。保底按实际成功到访计数，不包括折返。开发版原八次保底不变；发布版四条长途在每次未中后增加25个百分点，东京最迟第5次、伊斯坦布尔第4次、巴黎与冰岛第3次成功到访必得（v0.11.1调整）。

以冰岛为例，四份烤土豆远行盒提供48点补给，需土豆8、南瓜4、香草4。三块田地混种与提前储备能支持准备；旅程期间还能种田、做饭、读当天小书、聊天和布置小屋。没有新增强制每日签到、作物枯萎或离线惩罚。

## 开发版

保留既有秒至小时数值。体验加速的作物约为普通开发时间的1/10，旅程约为1/60，便于快速回归。发布版隐藏加速按钮且规则层拒绝切换；即使导入的存档记录 demo，也不会影响下一次发布版活动。

开发与发布存档目录分开；导入旧档仍保留已经开始的活动时刻。这是进度可迁移的单机设计，不是防作弊系统。

## 为什么不把所有东西都变慢

第一份香草便当约5分钟可以准备，近郊半小时内能体验首次归来。稻米等常用原料当天可多次收获；12–24小时作物适合睡前播种。最长旅行是自愿长线目标，其普通收藏能带来家居回报，稀有保底减少连续等待数月的可能。

七到十天仍有明显的陪伴空窗风险。建议小范围试玩后再决定是否把冰岛缩短为3–5天，或增加旅途途中便签与不发经济奖励的小互动。当前没有新增后台主动推送、途中任务或提前召回按钮；不要在宣传中暗示已有这些机制。

## 试玩观察

不把工程测试等同于用户耐心验证。下一轮至少记录：首次播种至首次归来完成率；一天内是否有可做的事情；长途出发后是否还愿意读书 / 种田；食材是长期短缺还是无限堆积；三次长途后奖励是否仍有意义。先用这些反馈调整作物时长、主食需求和长途跨度，避免继续单纯加内容数量。
