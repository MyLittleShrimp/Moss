# G1 交接：本地可玩闭环

日期：2026-09-09。状态：完成本轮 G1 范围。

## 可玩成果

18 秒香草生长 → 收获 → 做便当 → 35 秒溪谷旅行 → 获得来信及青石 → 摆在窗台。三块花圃独立生长，旅行时仍可操作庭院。宠物使用原创透明贴图与程序运动，归来后重新出现，摆放纪念品后会偶尔靠近窗边。

雨声偏好会影响出发快照及归来的本地规则信件。可以输入“我喜欢雨声”“我不喜欢雨声”，或使用忘记按钮。偏好和来源能在记忆页查看。存档可重载，已开始的旅行能在重新打开时结算。

## 代码入口与职责

| 文件 | 职责 |
|---|---|
| `scripts/world.gd` | 规则、资源、时间、命令、事件、存档和备份恢复 |
| `scripts/local_dialogue.gd` | 少量明确表达的规则识别与回复；未来提供器替换边界 |
| `scripts/main.gd` | 场景 UI、贴图、动画、按钮、时钟刷新、截图验证流程 |
| `scenes/main.tscn` | 游戏入口 |
| `assets/cottage.png`、`assets/frog.png` | 当前原创背景和单姿势角色 |

## 数据与规则契约

- 存档 schema=1，`user://moss_save.json`；`fresh()` 定义字段。
- `command()` 是业务修改入口，库存与旅行奖励由规则发放。
- 空地点击种植并浇水；成熟点击收获；未成熟拒绝重复操作。
- 做饭消耗一份香草，旅行消耗一份便当，不能同时开启两趟旅行。
- `advance()` 只结算一次已到期旅行，先更新状态再保存。
- 相同请求键保留最近 100 个，只用于本地演示防重复；不是生产 MCP 的完整幂等/版本/并发实现。
- 出发时冻结雨声偏好；途中纠正不重写已确定的经历，下一趟使用新偏好。
- 忘记清除当前偏好和来源，不删除历史来信。UI 明确说明这一点。

## 运行和验证

双击 `StartGame.cmd`，或 `./run.ps1`。完整操作路线见 README。23 项规则测试覆盖资源守恒、非法动作、错误地块、重复结算、记忆和损坏存档恢复；原生 UI 流程已通过。

## 已知限制

不是 live LLM；只有一个目的地和一种纪念品，没有随机事件库。只有单姿势角色与程序运动，没有八组逐帧动画、完整寻路或前景遮挡。当前单窗口、单用户本地状态，不支持同时运行两个实例写同一存档，也没有服务端时钟和反作弊能力。备份为单份上一版本，不替代正式迁移或云备份。

画面角色位置是表现层，不改变资源状态；天气偏好目前只影响叙事，不改变背景天气。没有声音、推送和付费。

## 后续开发要求

先保留上述规则测试，扩展真实 LLM 提供器时增加输出校验与故障降级，不让模型输出任意状态补丁。计划上线远程 Agent 之前，必须引入身份、服务端权威状态、事务、持久幂等键、版本冲突和权限检查；不能直接暴露本地 `world.data`。
