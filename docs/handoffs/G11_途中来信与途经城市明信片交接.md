# G11 途中来信与途经城市明信片交接

日期：2026-09-12。Godot 4.6.2 / GDScript。v0.11.0 功能切片；原始产品路线图仍未全部完成。

## 最终实现

小屋顶部「途中信箱」和生活手账「信箱」页展示途中来信、未读数量、寄出日期及所属旅程。可展开风景明信片或纯文字信纸；阅读状态保存。正文、祝福、落款均在纸面可见区域。

| 目的地 | 途经路线（按先后顺序） |
| --- | --- |
| 东京 | 上海 → 东京 |
| 伊斯坦布尔 | 上海 → 迪拜 → 伊斯坦布尔 |
| 巴黎 | 上海 → 迪拜 → 伦敦 → 巴黎 |
| 冰岛 | 上海 → 迪拜 → 伦敦 → 斯德哥尔摩或哥本哈根 → 冰岛 |

这些是游戏里的多城慢游安排，不是最短航线或实时航班查询。途中有朋友改变目的地时，按已确定的实际目的地选择相应路径；提前折返不生成途中邮寄。终点本身的原有明信片仍在归来后获得，途中只寄途经城市的新图，不提前发放终点收藏或宝物。

## 随机规则

- 出发时固定途经路径、寄信格式、文案、是否寄出和时间，随旅行快照保存；重启和导入存档不会重新抽取。
- 冰岛北欧分支两城各50%。每个途经点78%寄明信片、12%寄信、10%没有寄出；每城每趟最多一次，不会先到伦敦再收到更早寄出的上海信。
- 时间以实际已抽取的旅行总时长分段。在 n 个途经点中，第 i 站（从0开始）寄出时刻为出发时刻 + 总时长×(i+U)/(n+1)，U随机在0.65–1.0之间。顺序固定，具体时刻不可预测，不显示寄信倒计时。
- 冰岛7–10天的四站路线，通常每隔约一两天有机会收到消息；漏寄会让间隔变长，并非严格每日或隔日保证。东京更短，第一站可能在当天寄出。开发版沿用相同顺序，随快速旅程一起缩短。
- 离线回来时补投所有已经到时的途中信，然后独立处理最终归来。没有后台进程、外部邮件或推送。补投不重复，不改变原有返程时刻、奖励、保底或食物。
- 同趟城市不重复；不同旅程可再次收到同一城市，目前每城一张预生成风景、两段本地候选手记。不是每次实时生成新图片或LLM正文，不消耗玩家模型额度。
- 信箱保存最近60封，按最新寄出时间在前显示；这是收件箱排序，实际投递时序仍从上海往后推进。

## 存档兼容

保留schema7，增加可选 travel_mail 数组；trip_snapshot 内增加 mail_route_version=2、mail_route和mail_schedule。校验时间顺序、城市路径、同趟去重、记录ID、内容长度和数组上限。

旧存档没有这些字段仍能正常载入。旧在途旅行从升级时刻起，在剩余旅程中安排新来信；不补写升级前本不存在的信，也不改变旧终点和奖励。已经在途的新版本快照则保留原计划。导入导出连同阅读状态和未寄出的计划一起保存。原有多档、Key隔离和自动保存保留。
